# Contributing

## Setup and checks

Use current stable Rust with Cargo, rustfmt and Clippy, Git and native build tools.

```sh
cargo fmt --all
cargo fmt --all -- --check
cargo test --all-targets
cargo clippy --all-targets -- -D warnings
cargo build --release
cargo package --list
```

A Linux container with rustc 1.99.1, rustfmt and Clippy executed the full test,
Clippy, release build, packaging, installation and documented tutorial checks in
this pass. See the validation report accompanying the change for exact evidence.
The workflow runs tests, Clippy, release builds and package listing on Linux,
macOS and Windows; consult the latest Actions run before inferring cross-platform
results.

Cargo.lock is committed to pin reproducible builds. It was generated by Cargo
from the same manifest on a trusted network, not hand-authored. Use
`cargo test --locked` and `cargo build --locked --release` when reproducing
results. A `cargo audit` scan of the committed lockfile (RustSec advisory DB,
2026-11-10) reported no vulnerabilities and five informational warnings in
transitive dependencies: unmaintained `paste`, two unsound advisories in
`git2` itself, and two unsound advisories in `lru` 0.12.5 via `ratatui`
0.26.3. Upgrading `ratatui` would change the TUI API and is deliberately out
of scope; rerun `cargo audit` after any dependency change. git2 is built
without its
default ssh/https features because git-panic never performs network or remote
operations, so OpenSSL development files are not needed to build. serde_json is
a direct dependency for the documented, tested `--json` output of search and
recover.

## Architecture and safety

The single Rust binary in src/main.rs contains Clap definitions, HEAD reflog
extraction, literal filtering, the Ratatui/Crossterm inspector and branch creation.
Keep this small architecture and dependency footprint unless a concrete need
justifies a change. Recover previews by default; --create opts into a new branch
reference using force=false. Never add implicit checkout, reset, stash or remote
operations. Branch creation itself handles name races without force-overwriting.
It does not preserve uncommitted files, conflict resolutions or operation state.

A terminal guard attempts cleanup after ordinary errors, including partial setup.
The preserved release panic=abort setting, SIGKILL and some terminal failures can
bypass cleanup. Do not advertise universal rollback or restoration guarantees.

## Tests and manual validation

The suite has two layers: unit tests inside src/main.rs (repository fixtures
built directly against libgit2) and black-box integration tests in tests/cli.rs
that run the compiled binary via `CARGO_BIN_EXE_git-panic` against throwaway
repositories created with the real `git` CLI. Eighteen unit tests and fifteen
integration tests passed locally on rustc 1.99.1 in this pass (see the report
accompanying the change for exact commands). Manual checks covered the
documented tutorial, assistant workflow, JSON output, exit codes and pipe
handling. Fixtures create new repositories in unique OS temporary directories
using fixture identities, and remove them on drop. Never run destructive tests
in real worktrees. Coverage includes parser consistency, literal search,
control characters, broken-pipe behavior, empty reflogs, reflog extraction,
preview invariance, branch-name collisions (including the branch named HEAD),
bad objects, detached HEAD/index/staged/unstaged/untracked preservation, and
end-to-end recovery of a commit lost to `git reset --hard`.

Before merging, test:

- Interactive TUI navigation, Ctrl-C and narrow terminals:
  `cargo build --release --locked && python3 scripts/tui-pty-test.py`
  drives the real binary through a PTY (all keys, alternate-screen cleanup,
  long histories, 40-column rendering, Ctrl-C, and post-TUI terminal health).
- Resizing live and cleanup after injected terminal setup, read and draw errors.
- Rebase, cherry-pick and revert interruptions (merge conflicts were exercised).
- Concurrent name creation, bare repositories and linked worktrees.
- README installation and commands on macOS and Windows (Linux is verified;
  CI builds and tests on all three).

## Documentation and visuals

Embedded README artwork lives in assets/. The workflow SVG is original, static and
explicitly labeled illustrative, not a screenshot. The terminal capture
(assets/demo-terminal.svg) is generated by scripts/render-demo.sh from real
git-panic output in a disposable repository; rerun that script instead of
editing the image by hand. Never expose secrets or private history in fixtures,
output or recordings.

Keep README and help aligned with implementation. Do not add publication, speed,
passing-test or recovery claims without evidence. SECURITY.md is currently the
GitHub template with placeholder version and reporting text; it does not yet
describe a real supported-versions policy or vulnerability route. Fill it in with
verified details before pointing users to it, and do not post secrets or
sensitive exploit details publicly.

## Compatibility and licensing

Default/query/tui/snapshot syntax is preserved. Snapshot now fails instead of
falsely succeeding. Search output uses full SHAs and explicit HEAD@{n} labels;
consumers parsing human-readable output may need adjustment. R is still not a
restoration action. The source uses IsTerminal (Rust 1.70+); dependency MSRV has
not been verified. The full-SHA recovery command targets Git SHA-1 commits.

Leave the MIT manifest declaration unchanged. Ask the maintainer to resolve the
missing LICENSE file rather than selecting licensing terms on their behalf.
